# 调查发现

## 阻断性

- 游戏页和聊天接口字段不一致的问题已修复，统一为带应用会话的共享契约。
- 场景生成请求、响应、鉴权与AI JSON校验已统一。
- 轮次没有递增，关系经营按钮绕过操作点扣减逻辑。
- 企业后台调用了不存在的 `reports` 和 `invite-code` API。

## 游戏完整性

- 所有 NPC 和软肋直接显示，没有落实隐藏与解锁机制。
- NPC画像已改为服务端按ID读取并注入提示词，不再信任前端画像。
- 所有 NPC 共用同一份浏览器内存对话历史。
- 刷新后对话丢失，没有服务端会话或数据库持久化。
- AI回复已携带受限的结构化状态尾部，校验失败时不修改状态；尚未持久化。
- 结算维度、诊断和建议大部分仍为固定内容。
- 多人房间仍使用演示玩家和 WebSocket 占位。

## 数据与资料

- 本地 Schema 有 14 张表，API 还使用多张未纳入本地模型的远程表。
- 最新完整脚本和人物表没有同步到应用 `assets/`。
- 关卡事件表与人物表的人名和岗位体系不一致。
- 评分公式 `C0` 存在无效引用和语法问题。

## 工程

- 依赖安装、TypeScript、ESLint、Next生产构建、tsup打包和HTTP 200启动探测已通过。
- pnpm 只允许 `esbuild`、`sharp`、`unrs-resolver` 执行安装脚本；`msw`保持禁用。
- ESLint全量扫描约125秒，生产启动输出Node `url.parse()`弃用警告和一条乱码路径错误，但未阻断HTTP 200。
- 外层Git和harness已建立，可追溯基线提交为`51365b4`。
- 页面元数据仍包含扣子模板默认品牌文案。
