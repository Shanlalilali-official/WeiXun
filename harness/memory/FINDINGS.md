## 2026-08-14：全量审计（AI / API / 状态机 / 前端）

- 认证无信任边界（AUTH-002）：`select_role` 无凭证签发任意角色 token；会话 token 为无签名 base64，可手工伪造并冒充任意 `u_<手机号>` 用户接管其存档与对话；34 个 API 路由中 18 个无 `authGuard` 且全仓无 middleware；`authGuard` 的 requiredPermission 从未被使用；RLS 仅 3/17 表按 service_role 收紧，其余 14 张 permissive allow-all。
- 全部随机数由客户端 `commandId` 播种（GAME-013）：`shouldNpcRespond` 为确定性 FNV-1a，邀约接受、礼品反应、合规审计的种子均含客户端 commandId。本地实测 cmd-14 使 10% 概率邀约通过、gift-36 使 severity-5 礼品躲过全部审计且合规扣分恒 0。
- 评分提示词与 Zod schema 不一致（AI-016）：riskReason 必填但提示词未提、dimensionDeltas 需英文 key 但只给中文、semanticFlags 6 布尔未列、长度上限 schema 有提示词无、无 JSON 示例、parseEvaluation 丢弃 parsed.error。这是协议失败反复发生的机械原因。
- 玩家文本可注入 system prompt 并绕过隐藏人物解锁（AI-017）：`preparedItems.title` 直插 system prompt；`key_contact` 解锁只靠回复正则、无服务端 support≥50 门槛。
- AI 输出未校验即持久化（AI-018）：confirmedFacts/commitments 只去重 slice(-12) 即成为权威 system text；publicValueEvidence 无过滤；模型 severity 直接 ×3 成合规扣分。
- 模拟时间边界缺陷（GAME-014）：17:00 后分钟双重计费、晚间非正式占用白天额度、18:00 边界可绕过“每日一次”、advance_phase 第 5 轮双审计。
- 结算缺陷（SCORE-003）：一句同时含“绩效”与“个人绩效”时同时计入对公+个人两维度；evidence 声明为 string[] 致 strength 恒 2，两维度退化为条目数阶梯。
- 10 张幻影表 + 列名不匹配 + 部分路由静默吞错（BASE-008）；全量 ESLint 实测 29 个 `no-explicit-any`（BASE-007）；`start-project.bat` 曾不检测陈旧构建（ENV-006，已于 2026-08-14 修复并实测）。
- 台账校正：AI-010（跨 NPC 传话）与 AI-005（滚动摘要）此前标记已实现/Resolved，实际为死代码；BASE-007 错误数由 37 校正为 29；BASE-003 表数由 16 校正为 17。
- 已确认正确的部分：读操作不推进模拟时间（D-018 落实）；行动点不会被重复扣/退；`commit_game_command` 单事务 + 版本 CAS 幂等基本可靠；2/6/5 轮次上限与 480 分钟常量一致。

## 2026-08-12：隐藏人物剧情一致性

- 浏览器截图证明旧规则会在关系值达到 50 时直接显示陈建国，即使对话只说“上头”且没有披露姓名、职务；这是状态先于叙事的缺陷。
- 新规则将“允许披露”和“人物已发现”分离：亲密度 50 仅允许模型在相关追问下披露，服务端只在正文同时出现“陈建国”和业务部长身份时写入内部 `key_contact` 线索。
- 读取旧存档时会按 `key_contact` 重新派生可见人物，因旧规则误解锁且没有明确披露记录的陈建国会重新隐藏。
- 真实 E2E 证明：关系值 51 时仍隐藏；明确披露姓名与职务后解锁，并在刷新恢复后保持。

## 2026-08-12：NPC 偏好、跨人物信息与记忆核查

- 当前关系动作只有全局固定成本/基础亲密度，没有 NPC 级偏好；随后自动触发的 AI 回合会再产生 -8～+8 亲密度变化，但前端没有拆解两者来源。
- 当前消息查询和滚动摘要已经按 `sessionId + npcId` 隔离，每个 NPC 不会直接读取其他 NPC 的聊天记录；记忆存于数据库 JSON/消息表，不应改成难以并发和迁移的磁盘文件。
- 当前没有跨 NPC 报告事件。NPC 说“我去汇报”只是自然语言，不会让目标 NPC 获得该信息；反过来，直接共享所有对话又会造成 NPC 全知。
- 当前亲密度裸值会进入 NPC 提示词，并确定个人关注点/隐藏联系人能否披露；模型没有明确的关系分段行为规范，因此语气与信任程度仍可能随模型漂移。
- 当前没有事实与承诺来源账本；玩家虚构“上次你答应过”时，模型可能受措辞诱导，需要通过独立承诺记录和提示词核验修复。

## 2026-08-12：NPC 一致性第一版实现

- 关系经营维持混合机制：服务端先应用固定基础收益与 NPC 偏好修正，前端立即显示；对话完成后追加 AI 的本次沟通评价，三段来源均可见。
- 新人物仅在服务端状态本轮新增时触发发现弹窗，提供“立即对话”；存档刷新不重复触发。
- 跨 NPC 信息使用 `game_events`：回复中明确承诺汇报时创建 `npc.handoff.promised`，下一轮标记 `sent`，再下一轮标记 `received`；目标 NPC 只收到摘要。
- 每个 NPC 的 `conversationMemories` 新增已确认事实和该 NPC 承诺；系统提示明确要求 NPC 对无记录的历史主张要求证据。该抽取仍依赖模型，AI-011 保持开放待对抗测试。

## 2026-08-12：人物披露语序兼容与旧对局补偿

- 用户验收截图中，王经理已明确说出“业务部陈建国部长”，但旧判定只接受“业务部部长陈建国”等少数固定语序，因此未写入 `key_contact`，人物区和弹窗都没有更新。
- 判定已改为要求姓名与“业务部/部长”身份在同一句中近邻出现，兼容自然的中文语序，但不会因只有姓名或只有职务而误解锁。
- 对局读取时会对已存的 AI 回复做一次补偿扫描；发现符合披露条件的旧消息即写回线索和可见 NPC。前端用每局、每 NPC 的本地标记保证补偿后的发现提示只显示一次。

## 2026-08-12：快速闭环验收档

- `fast_acceptance / fastpass` 是独立的本地验收账号，用户 ID 决定倍率，普通账号和已有普通对局维持 ×1。
- 快速账号的新对局为 ×3：关系动作的基础值与人物偏好、AI 对话亲密度评价、AI 对话五维评分变化均由服务端放大后再持久化；操作点成本、轮次和分数上限保持原规则。
- 倍率会写入返回状态并显示在游戏页顶部；旧对局读取时默认 ×1，避免新增字段影响历史存档。
- 快速账号的顶栏增加“补行动点”按钮，单次输入范围为 1–999；服务端同时按快速账号用户 ID 和对局归属校验，并记录 `acceptance.action-points.replenished` 事件，不能只依赖前端隐藏按钮。

## 2026-08-12：连续对话亲密度不变化诊断

- 快速验收账号最近一局的 6 条 NPC 回复中，第 1 条结构化评分有效，模型原始 `affinityDelta=1`，按 ×3 保存为 `3`；第 2～6 条均为 `protocolValid=false` 且 `affinity_delta=null`，不是模型合理判定为 0。
- 当前模型在同一流式输出中同时生成角色正文和尾部 JSON；尾部标记缺失或 JSON 不满足 schema 时，服务端会保留正文但拒绝全部状态变化。这一安全边界正确，但单一混合协议的连续成功率不合格。
- 前端在已有正文时仅将 `AI_PROTOCOL_INVALID` / `AI_STATE_INVALID` 写入控制台，玩家不会看到本轮评分失败，表面上像“好感度没有变化”。修复需同时覆盖评分可靠性、确定性兜底和可见反馈。

## 2026-08-12：NPC 两阶段回复与评分

- 第一阶段仅使用 DeepSeek 流式生成 NPC 正文，不再要求模型在角色回复后拼接隐藏标记和 JSON；角色正文生成显式关闭思考模式，保留 0.7 温度以维持自然度。
- 第二阶段将人物身份、当前亲密度、轮次、最近 8 条对话、事实/承诺、玩家本轮输入和 NPC 实际回复交给独立评分器，使用 JSON Output、关闭思考、温度 0.1；schema 失败或供应商错误会自动重试一次。
- 两次评分均失败时由服务端确定性规则产生亲密度、原因、五维变化、正文可证实线索和可识别的具名汇报事件，保存 `evaluationSource=fallback` 并记录专门事件，不再产生无声的 `affinity_delta=null`。
- 前端每轮显示“评估中”及最终亲密度变化和原因；规则兜底时明确标记。真实 DeepSeek 独立评分返回 `source=model` 并通过 schema，强化 E2E 连续多轮验证正文、评分、状态持久化与结算通过。
