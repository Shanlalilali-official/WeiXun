# 调查发现

## 阻断性

- 游戏页发送 `location/scene/history`，聊天接口要求 `scenarioId/role/history`。
- 场景生成前端与接口的请求字段、响应字段和鉴权方式均不一致。
- 轮次没有递增，关系经营按钮绕过操作点扣减逻辑。
- 企业后台调用了不存在的 `reports` 和 `invite-code` API。

## 游戏完整性

- 所有 NPC 和软肋直接显示，没有落实隐藏与解锁机制。
- 具体 NPC 画像没有注入系统提示词，占位符未替换。
- 所有 NPC 共用同一份浏览器内存对话历史。
- 刷新后对话丢失，没有服务端会话或数据库持久化。
- 结算维度、诊断和建议大部分为固定内容。
- 多人房间仍使用演示玩家和 WebSocket 占位。

## 数据与资料

- 本地 Schema 有 14 张表，API 还使用多张未纳入本地模型的远程表。
- 最新完整脚本和人物表没有同步到应用 `assets/`。
- 关卡事件表与人物表的人名和岗位体系不一致。
- 评分公式 `C0` 存在无效引用和语法问题。

## 工程

- 当前没有 `node_modules`，尚未构建、类型检查或启动验证。
- 原目录不是 Git 仓库，缺少可追溯版本基线。
- 页面元数据仍包含扣子模板默认品牌文案。
