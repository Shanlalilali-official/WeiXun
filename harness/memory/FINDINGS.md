## 2026-09-22 沉浸式拜访实查

- 旧拜访界面不是缺少自由输入或 AI 链路；`meetingSend` 已经使用 `textarea` 和服务端 `visit_turn`。真正缺口是 `renderMeeting` 被限制在 `.workspace-body` 内，且只使用介绍头像和旧固定场景键。
- 动态场景 API 已通过 `/api/designer/image-assets` 返回 `visit_scene:<sceneKey>`，因此张建国样板可以精确读取 `visit_scene:leader_office`，不需要从“领导办公室”名称做不稳定正则推断。
- 愉悦度是服务端权威内部状态，正常恢复 DTO 不下发它。为了使用现有五档表情素材，最小安全契约是服务端返回派生枚举，而不是向页面暴露原始分数。

## 2026-09-22 UI 对比度与光学对齐实查

- `.bg-role-designer` 在 `globals.css` 中显式定义为以 `#F6F8FB` 为基色的页面背景径向渐变，它覆盖了同名 Tailwind 颜色工具类的预期；因此白色按钮文字几乎落在白色背景上。
- 两枚预览图标的外层图标盒尺寸、grid 居中和卡片排版本来就一致；确认缺口是两条 SVG path 的视觉重心不同，故只需独立微调内层 SVG，无需改变外层布局。

## 2026-09-21 场景素材 CRUD 实查

- 原实现的 `VISIT_SCENES`、slot 白名单和数据库 check 同时固定为 office/restaurant/elevator/bar；API 只有固定 slot 上传，故 UI 改成表格本身不能产生真实 CRUD，必须拆出独立记录表和写接口。
- 人物素材与场景素材的生命周期不同：人物有确定的 5+25 槽位，场景需要动态增删。独立表能避免为场景放宽 `designer_image_assets` 约束，从而保护已上传的 30 条人物素材。

## 2026-08-31：提示词 A/B 测试台

- 单套 `AI_*` 只能靠重启切换 Provider，不能形成同一输入的并行模型对照；命名 Provider 必须拒绝缺失配置，不能静默回退，否则会出现“两栏其实是同一模型”的假实验。
- 将 NPC 与 Evaluator 拆成两次调用后，Evaluator 的线索仍不能直接入状态：只有 `sourceQuote` 确实出现在 NPC 正文、且 `novel/actionable` 为真时才由 Resolver 接受。
- 方舟 Chat Completions 的基础地址为 `https://ark.cn-beijing.volces.com/api/v3`；`model` 应使用该账号、地域和 API Key 实际可用的 Model ID 或 Endpoint ID。普通文本请求成功不代表严格 `json_object` 评估契约一定成功，真实联调必须覆盖结构化返回。
- 首轮真实 A/B 使用中，两个模型分别把 `blockerUpdates` 输出为单对象、把 `newClues[].id` 省略。解决方式不是放宽最终 schema：只在 schema 前归一化这两种无损形状偏差，clue id 由 text+sourceQuote 确定性生成；其他不合法输出携带精确示例修复一次，仍失败则拒绝整轮且不写状态。
- 只保留 `history` 不足以形成可交付测试证据：它缺少每轮评估及状态前后快照，且有限历史会被截断。测试台现另存最多 100 轮的结构化 `records`，每轮绑定玩家话术、NPC 正文、Evaluator、变化量和 stateBefore/stateAfter；导出不再依赖最近历史拼接。
- 背景文案若只写在页面，会形成“测试者看到一种前情、模型收到另一种上下文”的隐性偏差。张建国两次既往接触、当前记忆、本次焦点、信息边界和初始状态现由 `PROMPT_TEST_SCENARIO` 单一预设供页面、模型提示和完整报告共同读取。
- “话术分类”不能替代可复现的多轮测试剧本。当前测试库按 6 套连续路径组织，每套 3–4 轮并标注本轮观察点；红线修复路径明确按“现金回扣/保证中标 → 只道歉 → 书面整改记录和复核材料 → 正式流程”执行，以命中确定性阻断和修复证据规则。
- 线索区过去只在存在阻断或正式线索时渲染，容易被误解为某个 Provider 丢失了字段。现固定显示阻断和已验收线索，并把 Evaluator 提出但未通过 Resolver 的候选线索单列；PDF 完整报告仍只纳入正式验收结果。
