# 决策日志

## 2026-09-23 Jev 人物画像与值预览

- D-081：Jev 可以沿用一套受限的题目 ID/类型/候选契约，但人物决策必须携带同源、逐人不同的静态决策画像；画像从项目一五人主档提取姓名、职责、个性、核心诉求、披露边界及禁忌等，不把面向写话 LLM 的整篇人物提示词直接塞入 Jev typed question。设计师可按人物只读查看将发送给 Jev 的静态画像真实值；当轮玩家文本、关系数值、历史和记忆仍由运行时组装，不跨用户保存或显示在全局配置页。

## 2026-09-23 Jev 设计师配置边界

- D-080：按用户要求给设计师提供 Jev `state`/`questions` 的查看与编辑入口。运行时动态 `state` 数据只读，开放每类任务的补充判断说明；每道题开放 `instructions` 文字覆盖，空值恢复代码默认。题目 ID、类型、候选键/范围、动态候选生成、合规硬规则、结果验证和最终状态写入保持代码控制。配置在既有配置表中用独立记录和版本管理，与人物提示词互不覆盖；仅后续默认 Jev 调用读取，不把真实玩家消息作为可长期编辑模板保存。

## 2026-09-23 五人预览账号隔离

- D-079：五人预览浏览器快照只在明确匹配当前 `weixun_identity.userId` 时恢复；旧版无归属的固定键不能证明属于当前用户，故首次升级时丢弃。按用户分别保存预览快照与会话 ID，同账号刷新可继续，换账号不能展示或提交上一账号缓存。服务端继续按会话 ID 与用户 ID 双条件查找，缺失与非当前用户使用相同 404 文案；不通过客户端切号操作删除旧账号的服务端会话。

## 2026-09-22 Jev 决策层

- D-077：用户批准以 Jev 作为独立决策层进行实验。AI 的 choice / score / yes-no 类输出由 Jev `state + typed questions` 完成；现有 OpenAI-compatible LLM 仅保留台词、理由、建议、摘要和方案等自由文本生成。混合调用必须拆成两步，不得通过解析 LLM 生成的决策字段回填状态。
- D-078：Jev 不并入 `src/lib/ai/client.ts` 的 chat-completions Provider 联合类型，而使用独立服务端客户端与 `JEV_*` 环境变量。Jev 失败时只允许进入已审计的确定性兜底，禁止静默回退到生成式 LLM 代做决策。安全硬规则、schema、来源核验、数值裁剪和服务端 Resolver 的优先级不变。

## 2026-09-22 沉浸式拜访样板

- D-076：五人预览的拜访首先以张建国办公室做沉浸式样板；会面进行中隐藏工作台外壳，主画面只保留场景、人物、NPC 对话、玩家自由输入和少量会面进度。人物表情由服务端愉悦度派生为五档枚举，客户端不获取原始愉悦度或支持度。本决定只覆盖预览样板，正式 `/game` 界面迁移待用户确认效果后单独进行。

## 2026-09-21 场景素材记录化

- D-075：拜访场景不再是 `designer_image_assets` 中四个固定槽位，而是独立 `designer_scene_assets` 业务记录，允许设计师增删查改名称、唯一标识、说明与图片。人物介绍和表情图片继续保持固定槽位约束；场景管理完成不自动等同于正式游戏已采用，地点匹配规则须另行确认。

## 2026-09-21 台账治理

- D-071：台账不再作为判断实现状态的唯一事实源。任何新增或修复前必须核对实际代码、迁移、权威数据库/对象存储和测试；涉及外部状态而无法访问时必须写明未实查，不得推定已完成或未完成。
- D-072：实现类变化与四份核心进度台账必须同批发生，并由 `harness-check.ps1` 自动阻断遗漏。自动门只证明台账被同步触碰；状态真实性继续由证据驱动、双向复核和人工 Review 保证。

## 2026-09-21 正式五人切换

- D-073：旧四人正式存档直接删除，不做人物 ID、状态、消息或关系映射。删除只命中持久化内容明确包含旧四人 ID 的项目一存档/房间及其级联子数据；preview、prompt-test、人物素材、设计配置、用户和企业数据不属于删除范围。
- D-074：正式项目一唯一玩家入口和权威状态使用 `/game`；五人主档派生正式人物配置，单机与联机基础建局均为 `P1-001`～`P1-005`。`/project-one-preview` 继续作为设计/测试设施，不与正式存档双写。多人实时广播保持延期，不影响正式人物切换完成状态。

## 2026-09-21 持久化与竞品能力

- D-066：五人预览和提示词测试使用各自独立的 Supabase JSONB 会话/命令表解决跨重启与多实例一致性；这是测试/预览基础设施，不替代 FRONT-006 的正式五人业务存档。命令必须同时使用用户作用域、唯一 commandId、规范化请求哈希、expectedVersion 和可续租短租约；失败不提交候选状态，但保留命令哈希以拒绝改包重放。
- D-067：五人预览恢复接口只返回继续操作所需的玩家可见状态。支持度、愉悦度、阻断、工作记忆、Evaluator 原因、附件正文和竞品隐藏动作均不得进入普通恢复 DTO；完整审计另设权限化 DTO。
- D-068：单机竞品每阶段优先使用结构化模型候选，但模型不得直接写最终影响。服务端校验候选并由确定性 Resolver 计算影响；协议/Provider 失败使用确定性兜底，隐藏动作只写内部事件。多进程外部调用完全去重随共享执行设施继续加固。
- D-069：设计师竞品配置复用 `scenario_templates.competitors`，不新建重复业务主表；写入采用 revision 乐观并发、权限校验和明确冲突刷新。多人实时同步按本批用户要求延期，不因竞品配置完成而扩大范围。
- D-070：已上传的 25 张人物表情图视为受保护现有资产，本批只验证不覆盖。运行时表情映射必须另有明确的状态/情绪规则后再实施；素材存在不等于游戏已使用。

## 2026-09-16 已读不回提示词范围

- D-058：不把服务端已读不回协议全文作为独立可导入字段。它包含模型输出结构、合规必须拒绝、沉默不构成承诺或披露等系统边界，开放改写会破坏状态契约。人物何时倾向沉默的角色偏好继续写入现有“人物总提示词”或邮件/工作微信“渠道补充”；这两类提示词已进入五人预览生成链路并随 Excel 导入导出。
