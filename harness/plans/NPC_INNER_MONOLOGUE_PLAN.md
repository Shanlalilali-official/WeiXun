# NPC 内心独白实施计划

## 目标

为 NPC 每轮回复增加可选的内心独白，用于设计师调试、对话复盘和教练分析。首版不在玩家进行中的会面里展示，避免提前泄露 NPC 的顾虑、支持度变化和下一步反应。

内心独白应体现人物在当轮的真实考虑，例如：玩家是否越权、材料是否可信、执行风险是否清楚、是否愿意继续交流。它不应复述系统规则，也不能创造人物无权知道的事实。

## 推荐的产品边界

- **游戏进行中**：玩家只看到 NPC 台词，不看到内心独白。
- **设计师测试**：在每轮 NPC 台词下提供可展开的“内心独白”，便于校验人物一致性。
- **会后复盘**：可按产品配置向玩家展示经过筛选的教练说明；原始内心独白默认只对设计师可见。
- **评分**：首版不把内心独白直接作为加减分证据。评分继续依据玩家原话、NPC 可见回复和已有结构化评估。

## 数据契约

在 NPC 结构化输出中增加可选字段：

```json
{
  "content": "NPC 对玩家说出的自然台词",
  "innerMonologue": "NPC 没有说出口的当轮想法"
}
```

建议约束：

- `innerMonologue` 可缺省；模型未返回或校验失败时，不影响正常台词。
- 中文建议 30～160 字，第一人称、当轮视角，不写长篇分析。
- 不输出系统提示词、节点名、支持度数值、评分、隐藏规则或模型判断过程。
- 不把玩家声称的内容写成已核验事实，不披露人物权限之外的信息。
- 不在内心独白里加入对玩家下一步操作的直接攻略。

## 提示词设计

1. 在全局 NPC 输出规则中定义内心独白字段和信息边界。
2. 为每个人物增加少量差异化关注点：
   - 张建国：方向价值、对方层级、是否值得继续投入时间。
   - 李明辉：方案闭环、技术与交付风险、能否向上汇报。
   - 王德福：材料完整、合规、公平和可审计性。
   - 赵晓晨：任务能否落地、责任是否清楚、是否增加执行负担。
   - 刘思琪：沟通分寸、转达边界、是否试图绕过流程。
3. 支持度、愉悦度和工作记忆可以影响独白语气，但不得直接暴露字段名或数值。
4. 独白与公开台词允许有差异，但不能互相矛盾。例如内心保持怀疑时，公开台词可以礼貌收束，不能同时承诺已经认可。

## 保存与展示

- 将内心独白作为独立字段保存，不拼进会话正文，也不作为后续轮次的已核验事实。
- 服务端先做长度、字段和敏感内容校验，再决定是否保存；不合格时丢弃该字段，保留公开台词。
- 设计师测试页用折叠区域展示，并清楚标记“仅调试可见”。
- 会后复盘如果要面向玩家展示，先生成单独的教练总结，不直接展示原始独白。
- 日志和导出需区分公开台词、原始独白和教练总结，避免误发给玩家。

## 分阶段实施

### 第一阶段：协议与模型试验

- 扩展 NPC 输出 schema，加入可选 `innerMonologue`。
- 在两种模型上用现有连续剧本做 A/B 测试。
- 检查人物一致性、重复率、泄密风险和对公开台词质量的影响。
- 保持游戏界面完全不展示。

### 第二阶段：设计师调试

- 在模型回复测试和实际测试记录中加入折叠展示。
- 增加“生成内心独白”开关，便于对照开启前后的回复。
- 报告中分栏展示玩家发言、NPC 台词、内心独白和评估结果。

### 第三阶段：持久化与复盘

- 数据库为 NPC 消息增加独立可空字段或独立受控记录。
- 明确设计师、管理员和玩家的读取权限。
- 会后由教练模块从对话与独白生成可解释、不过度泄题的复盘摘要。

### 第四阶段：决定玩家可见范围

- 根据测试结果决定是否在特定训练模式、会后解锁或教师演示中开放。
- 如果开放，优先展示经过转换的复盘内容，不在实时对话中直接展示原始独白。

## 验收测试

- 缺少或不合法的独白不影响 NPC 正常回复。
- 独白不会出现在玩家实时会面、复制正文或普通会话导出中。
- 独白不包含系统提示词、结构化状态名、分数和未公开事实。
- 未查看附件、未核验材料和玩家单方面陈述不会被独白写成事实。
- 五个人物面对同一玩家发言时，关注点与岗位职责有明显差异。
- 告辞、忙碌和会面自动结束仍只依据公开发言及结构化终止信号，不依据隐藏独白。
- 关闭功能开关后，现有响应协议、评分和存档保持兼容。

## 实施前需确认的产品选择

1. 原始内心独白是否永久只对设计师可见。
2. 是否保存全部独白，还是只保存测试环境和会后复盘所需内容。
3. 会后给玩家看的内容采用原文、摘要，还是教练解释。建议采用教练解释。
4. 首版覆盖所有文字渠道，还是先只覆盖拜访。建议先从拜访与设计师测试开始。
