# 项目上下文

## 用户与角色

- 玩家：参加单人或多人竞标实训。
- 培训教练：发起训练、组织房间、观察和点评。
- 企业管理员：管理学员、任务、邀请码和报告。
- 平台设计师：管理项目、NPC、竞品、指标、公式和提示词。

## 核心业务链路

```text
登录与身份
→ 选择/生成项目
→ 创建对局
→ 查看初始人物与目标
→ 选择 NPC 并行动/对话
→ 更新轮次、亲密度、线索与竞品状态
→ 解锁隐藏角色或事件
→ 中标/落标判定
→ 评分、复盘、排行榜与历史
```

## 当前实现概况

- 页面：登录、工作台、选关、配置、游戏、结算、排行榜、知识库、房间和三类后台均已有页面。
- API：已有登录、AI 对话、场景生成、游戏数据、排行榜、教练和企业管理接口外壳。
- 数据：本地 Drizzle Schema 定义 14 张表，但部分 API 使用额外远程表。
- AI：通过 Next.js 服务端路由调用 `coze-coding-dev-sdk`；NPC 对话采用前端重发全部历史的方式模拟多轮上下文。
- 素材：外部素材库较完整，应用只接入其中少量图片和旧版文档副本。

## 当前关键风险

- 资料不是单一事实源。
- AI 接口前后端参数不一致。
- NPC 人格和游戏状态未真实注入提示词。
- 对话历史只保存在浏览器内存，且所有 NPC 共用。
- 轮次、操作点、线索解锁和结算未形成闭环。
- 数据库本地模型、远程表和页面调用范围不一致。
